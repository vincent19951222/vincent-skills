# 叙事模式与布局选择

先选叙事，再选视觉形式。一个内容分类允许采用不同叙事。

| 叙事模式 | 问题 | 主要画面 | 信息深度 |
|---|---|---|---|
| Overview → Detail | 系统由什么组成？ | 简洁架构 / Node Graph | 节点 → 角色 → 参数/证据 |
| Problem → Mechanism → Solution | 问题如何形成和解决？ | 因果链 / 机制示意 | 问题 → 机制 → 方案证据 |
| Before → After | 改变发生在哪里？ | 同维度双栏 / 差异强调 | 结果 → 差异 → 依据 |
| System → Component | 局部如何服务整体？ | 总览与选中局部 | 系统 → 子系统 → 实现 |
| Data → Insight | 数字说明什么？ | 一个主指标 / 有来源趋势 | 数值 → 判断 → 限制 |
| Timeline → Event | 事情怎样演进？ | 时间主轴 | 事件 → 原因 → 证据 |

## 响应式

投屏模式优先接近 16:9；普通窗口和手机保证内容完整，不用固定高度裁掉正文。桌面 12 列，手机主画面改成纵向顺序；关系方向与返回入口保留。缩放功能要有按钮替代手势。

## 一屏检查

一个核心问题、一个视觉主角、最多三个主要信息组。静态截图仍能解释 L0/L1；不以“未播放动画”为由显示空白或残缺画面。
