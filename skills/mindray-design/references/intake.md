# Project intake

Before designing, gather enough information to distinguish a real course from a generic demo. Do not block on optional answers.

## Required facts

| Field | Question | Evidence |
|---|---|---|
| Audience | Who will use or present this? | role, department, training context |
| Objective | What should the viewer understand or do? | one sentence outcome |
| Source set | Which PDFs, screenshots, notes, or data are authoritative? | filenames or links |
| Scope | Which product, version, environment, or workflow? | version and boundary |
| Delivery | Direct-open HTML, hosted page, or embedded deck? | target environment |

## Useful optional facts

- presenter controls and keyboard requirements
- whether the deck is used live or read asynchronously
- which steps need reveal or drill-down
- known terminology and abbreviations
- which content is confidential and must remain local

If source material conflicts, preserve both claims with source labels and ask which is authoritative before presenting a single answer. Never fill a missing product fact with plausible medical language.
