# Vincent Pixel 配图

把中文内容里的关键判断、流程、状态和隐喻，转成欢快、温暖、清晰的等距 16-bit 像素场景。微信公众号头条封面使用 2.35:1，通用封面、正文配图和小红书 HTML 卡片内嵌主视觉使用 16:9。每张图只讲一个核心意思，并让 Vincent 作为 Builder 亲自完成使概念成立的动作。

## 先读取

按任务读取，不要一次加载全部参考：

- 始终读取 `references/visual-system.md` 和 `references/vincent-ip.md`。
- 规划或生成新图时读取 `references/composition-patterns.md`。
- 调用生图工具前读取 `references/prompt-template.md`。
- 生成后读取 `references/qa-checklist.md`。
- 使用 `assets/vincent-avatar.png` 作为唯一人物身份参考，优先校准脸型、眉眼比例、发型、圆框眼镜和胡须。服装、成人比例和动作只按 `references/vincent-ip.md` 的文字规则构建。不要引用相邻 Skill 中的角色板；头像不是像素画风参考，最终画风以本 Skill 为准。

## 判断入口

- 用户只要求“分析、建议、怎么配图、shot list”时，只输出配图策略，不生图。
- 用户明确要求“生成、直接生成、做图、输出图片”时，内部完成策略后直接逐张生图，不等待确认。
- 用户意图不清时，先输出 shot list。
- 用户要求修改已有图片时，进入局部编辑流程，不重新设计整张图。

## 选择资产类型

- **微信公众号头条封面**：使用 `2.35:1`，以 `900×383` 为参考尺寸，不写成近似的 21:9。用一个强主场景表达整篇文章，默认不把文章标题烘焙进图片。把 Vincent、核心物件和不可裁切信息集中在中央偏上安全区，左右两侧只放可裁切的场景延伸，底部不放关键内容。
- **通用博客封面**：使用 16:9。主体清楚，四周不过满；默认不把文章标题烘焙进图片，为后期标题保留稳定负空间。
- **正文配图**：一张只解释一个判断、步骤、状态或隐喻；默认直接生成 2–5 个简短中文像素批注，帮助读者看懂输入、输出、状态、转折或结果，但不重复文章标题。所有批注必须直接来自当前文章的主题与 shot list 白名单，不添加通用游戏状态或氛围文案。
- **小红书 HTML 卡片内嵌主视觉**：使用 16:9，只生成独立无字像素场景，供 `$vincent-design-system` 放入 1080×1440 HTML 卡片。不要生成最终 3:4 卡片，不烘焙卡片标题、正文、页码、徽章或品牌边框；这些由 HTML 负责。
- **公众号次条或分享方图**：只有用户明确要求时才另做 1:1 版本，不用 16:9 或 2.35:1 图片直接冒充。
- 正文配图只有在用户明确要求“纯图片、无字底图”时才不生成文字；小红书 HTML 卡片内嵌主视觉固定无字。需要图内文字时，所有文字都由图片生成模型直接生成，不使用脚本、Canvas 或后期排字叠加。

## 工作流

### 1. 提炼认知锚点

读取用户提供的正文、Markdown、文件、链接、截图或观点。提炼核心判断、认知转折、输入输出、前后差异、断点、角色状态和适合物理化的抽象概念。

不要平均配图。封面单独计算，正文配图按篇幅给出基础范围，再由有效认知锚点决定最终数量：

- **短篇，约 1500 字以内**：2–4 张正文图。
- **中篇，约 1500–3500 字**：4–6 张正文图。
- **长篇，约 3500–7000 字**：6–9 张正文图。
- **超长篇，约 7000 字以上**：9–12 张正文图。

需要封面时在正文图数量之外增加 1 张，总交付通常不超过 13 张。用户只要封面时只设计一张。

字数只决定初始范围，不按段落机械凑数。候选内容至少满足以下两项才算一个有效认知锚点：只读文字不容易快速理解；能转成清楚的物理动作或场景；与其他配图表达不重复。认知锚点不足时少画，特别密集时也优先合并相近意思。

### 2. 形成 shot list

每张写明：

- 放置段落或封面用途
- 发布平台与精确画布比例：公众号头条 2.35:1；通用封面、正文或小红书 HTML 卡片内嵌主视觉 16:9
- 图的主题与一句核心意思
- 物理隐喻
- 等距构图类型与主视线
- Vincent 的核心动作
- 主要物件和主色组合
- 严格文字白名单：正文图默认列出 2–5 个精确批注，并写明每个词的放置对象与解释作用；封面和小红书 HTML 卡片内嵌主视觉的白名单为空，只写裁切或嵌入位置要求

### 3. 逐张生成

每张只表达一个核心意思，并单独调用一次图片生成工具。

每次生成前先根据发布位置明确画布比例。公众号头条封面必须在提示词中直接要求 `2.35:1` ultra-wide canvas，并以 `900×383` 作为构图参考；通用封面、正文图和小红书 HTML 卡片内嵌主视觉使用 16:9。正文配图必须把 shot list 中确认的文字白名单直接写入本次 ImageGen 提示词，让模型在生成场景时同步生成文字；图内不得出现白名单之外的字符。小红书 HTML 卡片内嵌主视觉的文字白名单固定为空，并保留适合 HTML 卡片裁切的清楚主体。不要把卡片标题、正文或页码生成进图片后再试图修字。封面仍默认不烘焙文章标题。

禁止模型为了营造“像素游戏感”擅自在顶部或角落添加状态栏、Emoji、百分比、电量、心情、任务状态或设备标签，例如“👾 心情：编码中”“📡 AI：99%”“电源”。顶部如果确实需要文字，也必须是从当前文章提炼出的白名单批注，并直接解释画面中的主题关系。

优先使用当前环境原生 `image_gen`。生成前视觉检查头像，并通过当前工具支持的参考图机制把它作为唯一人物身份参考。要求主动匹配可辨识的面部相似度，而不是只提取“亚洲男性、眼镜、短发”等泛化标签；服装、成人比例和动作完全按文字规则生成。明确忽略头像的水彩渲染、光影和头像构图。

没有原生工具时，如果已安装 `$codex-imagegen`，读取其说明并用桥接器生成。两者都不可用时，说明缺失能力并交付完整提示词；不要假装已经生成，也不要静默切换到需要 API Key 的路径。

提示词必须基于 `references/prompt-template.md`。将用户提供的 `isometric pixel art...` 视为视觉合同：使用 ImageGen 时把平台比例写成自然语言约束；只有目标明确为 Midjourney 时才追加对应资产类型的参数，公众号头条用 `--ar 900:383`，通用封面、正文图和小红书 HTML 卡片内嵌主视觉用 `--ar 16:9`。

### 4. 编辑已有图片

把用户提供的图片作为编辑目标。若目标是本地文件，先用 `view_image` 检查，再调用原生编辑流程。只修改用户指定部分，保持人物身份、像素尺寸感、调色板、等距角度、构图、比例和其他文字不变。

默认写入新文件，不覆盖原图。只有用户明确要求替换时才覆盖。

### 5. 检查与迭代

按 `references/qa-checklist.md` 检查结果。出现伪像素滤镜、边缘发糊、透视混乱、人物身份漂移、Q 版化、场景过密、中文错字、白名单外文字或 3D 渲染感时，每轮只修一个主要问题，然后重新检查。正文批注出错时优先局部编辑或减少批注后重生成，不得静默删除全部文字并改交纯图片。

### 6. 保存交付

生成结果必须保存到用户当前的实际内容项目中，路径从该项目根目录计算。进入项目的 `assets/`，再按文章建立独立目录：

```text
<project-root>/assets/<article-slug>-pixel/
```

这里的 `<project-root>` 是文章、博客或内容文件所在项目的根目录，不是本 Skill 的安装目录。禁止把文章生成图写入 `vincent-pixel/assets/`；Skill 自身的 `assets/` 只用于保存头像等固定参考资产。

按顺序命名：

```text
00-cover.png
01-topic-name.png
02-topic-name.png
card-01-topic-name.png
```

不要覆盖已有资产；使用语义化新文件名或 `-v2`。预览型任务可以只在对话中展示。

交付时简要报告：资产类型、图片数量、每张用途、最终路径、使用的生成方式和最终提示词。指出最稳的必选图与可选图，不长篇解释风格理论。

## 边界

- 最终 3:4 小红书图文卡片或封面：使用 `$rednote-cover-gen` 或 `$vincent-design-system`；本 Skill 不直接生成最终卡片。
- 作为 `$vincent-design-system` 两步工作流中的第一步时，可生成供小红书 HTML 卡片内嵌的 16:9 无字像素主视觉。
- Vincent 极简线描正文插图：使用 `$vincent-illustrations`。
- 头像风格转换：使用 `$artifact-template-warm-paper`。
- HTML、Landing、App、公众号 HTML 排版：使用 `$vincent-design-system`。
- 不含 Vincent IP 的通用像素图：使用通用 Image Gen 能力。
- 需要精确网格、透明通道、逐帧动画或可投产 sprite sheet 的游戏资产：先改用专门的像素资产工作流，不把概念配图直接当成游戏成品。
