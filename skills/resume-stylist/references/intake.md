# 简历信息收集规范

> 用于第一次沟通。目标是复用已有信息、一次收齐必填缺口，避免连续零碎追问。

## 输入方式

优先接受以下任一种输入：

1. **旧简历**：文件、截图或粘贴文本 + 目标岗位/公司。
2. **从零创建**：填写下方标准信息表。
3. **只换风格**：现有简历 + 指定皮肤或风格偏好；默认保留原文。

先从用户材料中提取已有字段，再只询问缺失的必填项。不要要求用户重新填写已经提供的内容。

## 必填与可选

| 类别 | 必填 | 可选加分项 |
|---|---|---|
| 目标定位 | 意向岗位；目标公司名称或公司性质 | 招聘描述、工作地点、语言版本 |
| 基本信息 | 姓名；城市；至少一种联系方式 | 个人网站、GitHub、LinkedIn、作品集 |
| 工作经历 | 公司、职位、起止时间、主要工作或成果 | 团队规模、业务指标、获奖/晋升 |
| 项目经历 | 无工作经验时至少一个项目 | 开源、个人项目、Campaign、作品项目 |
| 技能 | 至少一个与岗位相关的技能组 | 熟练度、证书、语言能力 |
| 教育背景 | 学校、专业/学位、起止时间 | GPA、排名、竞赛、社团 |

没有量化数据不阻塞生成。保留可验证事实，并把可补充数字标记为待完善，绝不虚构。

## 标准信息表

让从零创建的用户复制填写；不知道或暂不公开的字段写“暂无”或“脱敏”。

```markdown
## 目标定位
- 意向岗位：
- 目标公司名称或性质：
- 招聘描述（可选）：
- 简历语言：中文 / 英文 / 双语

## 基本信息
- 姓名：
- 城市：
- 手机 / 邮箱（可脱敏）：
- GitHub / LinkedIn / 个人网站 / 作品集（可选）：

## 工作经历（每段复制一次）
- 公司 / 团队：
- 职位：
- 时间：
- 主要工作：
- 可验证成果或影响：
- 可公开数字（没有可留空）：

## 项目经历（可选；无工作经验时至少填写一个）
- 项目名称 / 角色 / 时间：
- 做了什么：
- 结果或影响：
- 项目链接（可选）：

## 技能
- 技能分组及具体技能：

## 教育背景
- 学校 / 专业 / 学位 / 时间：
- GPA、排名、竞赛或社团（可选）：

## 其他（可选）
- 证书 / 语言 / 奖项 / 出版 / 展览：
- 希望保留或删除的内容：
```

## 一次性追问格式

用户材料不完整时，按以下结构回复：

1. **已读取**：简要列出已经获得的信息，证明没有忽略用户材料。
2. **还需要**：只列缺失的必填项，合并成一次问题。
3. **可选补充**：列出能增强简历但不阻塞生成的内容。
4. **隐私提示**：联系方式可以先脱敏，不要求公开敏感信息。

## 完成条件

满足以下条件即可进入皮肤推荐：

- 已知意向岗位，以及目标公司名称或公司性质。
- 已知姓名、城市和至少一种联系方式（允许脱敏）。
- 时间线中的每段主要经历都有主体、角色、时间和至少一项工作事实。
- 已有教育背景和至少一个岗位相关技能组。
- 没有把未知信息当作事实补入。

可选信息缺失时继续流程，并明确标记后续可补充，不要反复追问。
